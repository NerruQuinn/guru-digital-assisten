New_App_LessonPlannerUI
Bagian src-components-pages
a. Dashboard.jsx (Main Layout Controller): Komponen induk yang berfungsi sebagai pusat navigasi aplikasi dengan mengelola state activePage; file ini bertanggung jawab atas logika conditional rendering pada fungsi renderPage untuk memuat halaman yang berbeda, serta mengatur struktur tata letak utama (layout shell) yang menggabungkan Sidebar, Header, dan area konten utama.
b. LoginPage.jsx (Authentication): Entry point aplikasi yang menangani alur masuk pengguna menggunakan metode signInWithOAuth dari Supabase; file ini merupakan lokasi utama untuk pengecekan konfigurasi provider Google dan manajemen pengalihan (redirect) URL setelah proses autentikasi berhasil atau gagal.
c. DashboardPage.jsx (AI Generator Input): Halaman formulir utama yang menangani pengumpulan data input pengguna (Jenis Materi, Mapel, Kelas, Topik) melalui elemen select; file ini adalah tempat di mana data akan diproses sebelum dikirim ke API AI, serta memiliki komponen preview statis yang harus dihubungkan dengan state hasil generate nantinya.
d. TemplatesPage.jsx (Document Management): Komponen pengelola berkas yang melakukan pemetaan (mapping) array documents ke dalam tabel; file ini berisi logika visual untuk membedakan ikon berdasarkan tipe file (RPP vs Nilai) dan merupakan lokasi di mana kamu harus memperbaiki fungsi aksi (event handlers) untuk tombol view, download, dan delete.
1.2 Bagian SRC-Components
a. Dashboard.jsx: File ini adalah Main Layout (Parent Component) yang berfungsi sebagai pengatur navigasi utama aplikasi menggunakan State Management (activePage); file ini mengontrol perpindahan halaman antara TemplatesPage, HistoryPage, dan DashboardPage secara dinamis melalui fungsi renderPage, serta membungkus seluruh konten dalam struktur flexbox yang mengintegrasikan Sidebar dan Header secara konsisten.
b. Header.tsx (Stateless UI Component): Komponen reusable yang berfungsi untuk menampilkan navigasi hierarkis (breadcrumb) dan judul halaman secara dinamis melalui props title serta breadcrumb; file ini merupakan area utama untuk memodifikasi elemen antarmuka bagian atas aplikasi, termasuk penyesuaian profil pengguna pada tombol User dan pengaturan konsistensi desain border-bottom pada setiap halaman.
c. Sidebar.tsx (Navigation Component): Komponen navigasi vertikal yang mengontrol alur aplikasi melalui props onPageChange; file ini menyimpan konfigurasi menu dalam array menuItems dan menggunakan logika conditional styling untuk menandai halaman aktif berdasarkan props activePage. Jika terjadi kesalahan navigasi atau ikon tidak muncul, periksa pemetaan ID pada menuItems dan pastikan fungsi callback dari komponen parent (Dashboard.jsx) terhubung dengan benar ke setiap tombol menu.
1.3 Lib
a. supabase.js (Backend Configuration): File konfigurasi utama yang membangun koneksi antara aplikasi frontend dan layanan Supabase menggunakan createClient; file ini sangat krusial untuk dipantau jika terjadi kegagalan autentikasi atau pengambilan data, karena bertanggung jawab memvalidasi variabel lingkungan (.env.local) serta menyediakan log error pada konsol browser jika VITE_SUPABASE_URL atau VITE_SUPABASE_ANON_KEY belum terkonfigurasi dengan benar.
1.4 SRC
A. App.tsx (Root Component & Guard): File inti aplikasi yang berfungsi sebagai Auth Gate dan pengatur layout utama; file ini bertanggung jawab mengelola state session menggunakan useEffect untuk memantau perubahan status login melalui onAuthStateChange dari Supabase, serta melakukan pengalihan otomatis ke LoginPage jika sesi tidak ditemukan, menjadikannya titik pertama yang harus diperiksa jika aplikasi mengalami masalah akses atau gagal memuat konten setelah login.
b. index.css (Global Stylesheet): File pusat konfigurasi gaya yang mengintegrasikan direktif Tailwind CSS (base, components, utilities) dan menetapkan standarisasi tipografi global menggunakan font Inter serta sistem fallback font modern; file ini adalah tempat utama untuk melakukan kustomisasi desain dasar aplikasi atau memperbaiki masalah visual yang muncul secara menyeluruh pada elemen HTML dasar (seperti body).
c. main.tsx (Application Entry Point): File ini adalah titik awal eksekusi seluruh aplikasi React yang bertanggung jawab untuk menghubungkan komponen root (App.tsx) ke elemen DOM HTML (id root); di sini terdapat pembungkus StrictMode yang sangat berguna selama fase pengembangan untuk mendeteksi potensi masalah pada siklus hidup komponen, sehingga jika aplikasi gagal merender sama sekali atau terjadi error pada tingkat paling dasar, file ini adalah tempat pertama yang perlu dipastikan integritasnya.
General
a. .env.local (Environment Variables): File konfigurasi rahasia yang menyimpan kredensial akses API untuk Supabase, yang terdiri dari URL proyek dan Anonymous Key sebagai jembatan otentikasi; file ini adalah titik kritis yang harus diperiksa jika konsol browser menampilkan pesan error "Key tidak ditemukan", dan sangat penting untuk diingat bahwa setiap perubahan pada file ini memerlukan proses restart server development (npm run dev) agar variabel baru dapat terbaca oleh sistem Vite.
b. eslint.config.js (Linting Configuration): File ini mengatur standarisasi kualitas kode dan aturan penulisan (coding standards) untuk TypeScript dan React; ia berfungsi untuk mendeteksi potensi kesalahan penulisan secara otomatis melalui integrasi tseslint dan react-hooks, serta memastikan fitur Hot Module Replacement berjalan lancar melalui react-refresh. Jika kamu menemukan peringatan (warning) atau error saat melakukan kompilasi terkait sintaksis atau aturan React, file inilah yang menjadi acuan utama untuk menyesuaikan atau menonaktifkan aturan tersebut di bagian rules.
c. index.html (HTML Entry Point): File ini adalah kerangka dasar (struktur luar) dari seluruh aplikasi web kamu; ia berfungsi untuk memuat font eksternal (Inter), mengatur metadata untuk kebutuhan SEO dan tampilan media sosial (Open Graph), serta menyediakan elemen kontainer tunggal <div id="root"></div> yang menjadi tempat bagi React untuk menyuntikkan seluruh antarmuka aplikasi melalui skrip main.tsx. Jika aplikasi tidak muncul di browser atau font tidak berubah, periksa apakah skrip pemanggil dan tautan Google Fonts di file ini sudah benar.
d, package.json (Project Manifest): File ini adalah daftar isi teknis dan konfigurasi dependensi seluruh aplikasi kamu. Di sini tercatat bahwa proyek kamu menggunakan React 18, Supabase untuk database/auth, dan Lucide-React untuk ikon; file ini juga mendefinisikan script perintah (seperti npm run dev) serta mengatur versi library yang dibutuhkan agar aplikasi berjalan dengan stabil.
e. package-lock.json (Dependency Tree): File ini adalah catatan detail dan terkunci dari semua sub-dependensi (seperti Babel, ESBuild, dll.) yang terinstal di folder node_modules; fungsinya adalah memastikan bahwa setiap orang (atau server) yang menjalankan proyek kamu menggunakan versi paket yang identik secara presisi, sehingga mencegah bug yang disebabkan oleh perbedaan versi library pendukung.
f. postcss.config.js (CSS Processor Configuration): File ini berfungsi sebagai konfigurasi untuk PostCSS, alat yang memproses CSS kamu sebelum dikirim ke browser; di sini, Tailwind CSS didaftarkan sebagai plugin agar semua utility classes (seperti flex, bg-blue-500) bisa diubah menjadi CSS murni, sementara Autoprefixer otomatis menambahkan vendor prefixes (seperti -webkit- atau -moz-) pada properti CSS tertentu agar tampilan aplikasi kamu tetap konsisten dan tidak berantakan di berbagai browser (Chrome, Safari, Firefox).
g. tailwind.config.js (Styling Configuration): File ini adalah pusat kendali desain aplikasi kamu yang menentukan bagaimana Tailwind CSS memproses style; bagian content sangat krusial karena memberi tahu Tailwind untuk memindai file HTML dan komponen React kamu agar hanya men-generate CSS yang benar-benar digunakan, sementara bagian theme.extend adalah tempat di mana kamu bisa menambahkan kustomisasi warna, ukuran, atau font khusus agar seragam di seluruh aplikasi.
h.tailwind.config.js (Styling Configuration): File ini adalah pusat kendali desain aplikasi kamu yang menentukan bagaimana Tailwind CSS memproses style; bagian content sangat krusial karena memberi tahu Tailwind untuk memindai file HTML dan komponen React kamu agar hanya men-generate CSS yang benar-benar digunakan, sementara bagian theme.extend adalah tempat di mana kamu bisa menambahkan kustomisasi warna, ukuran, atau font khusus agar seragam di seluruh aplikasi.
i. tsconfig.json (TypeScript Configuration): File ini adalah pusat peraturan untuk TypeScript compiler yang menentukan bagaimana kode .ts atau .tsx kamu divalidasi dan dikonversi menjadi JavaScript; di sini diatur penggunaan standar ES2020, integrasi dengan React JSX, serta aturan linting ketat seperti strict: true yang mewajibkan penulisan tipe data yang jelas guna mencegah bug logika sebelum aplikasi dijalankan.
j. tsconfig.json (Solution Configuration): Ini adalah file induk atau entry point untuk konfigurasi TypeScript dalam proyek kamu; alih-alih mengatur aturan kodingan secara langsung, file ini menggunakan fitur Project References untuk memisahkan logika aplikasi utama (tsconfig.app.json) dengan konfigurasi lingkungan server-side atau build tools seperti Vite (tsconfig.node.json). Pemisahan ini sangat penting untuk memastikan bahwa aturan kodingan untuk browser tidak tercampur dengan aturan untuk Node.js, sehingga proses compilation menjadi lebih cepat dan terorganisir.
k. tsconfig.node.json (Build Tools Configuration): File ini adalah konfigurasi khusus TypeScript untuk lingkungan Node.js, yang secara spesifik hanya menangani file konfigurasi build seperti vite.config.ts; dengan target ES2022, file ini memastikan bahwa proses pengembangan dan bundling aplikasi menggunakan standar JavaScript modern yang optimal untuk tools seperti Vite, tanpa mengganggu aturan kodingan utama yang berjalan di browser.
l. vite.config.ts (Build Tool Configuration): File ini adalah pusat kendali untuk Vite, yang mengatur bagaimana aplikasi kamu dikompilasi dan dijalankan saat pengembangan; di sini, plugin @vitejs/plugin-react diaktifkan agar fitur-fitur React berjalan optimal. Bagian optimizeDeps yang mengecualikan lucide-react sering digunakan untuk memastikan ikon-ikon dari library tersebut dimuat dengan benar tanpa masalah caching yang sering terjadi pada paket-paket ikon besar.
